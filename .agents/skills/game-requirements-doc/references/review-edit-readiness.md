# 需求修改与复核

- 审阅前从项目路径回读当前需求、相邻模块引用和适用决策。记录需求版本。实现用于核对现状，正式预期来自已确认的需求。
- 新建或修改时只动本轮范围。先保留已有玩家行为，再检查修改涉及的术语、阶段、引用、表格和验收场景是否仍对得上。纯审阅交付结论和必要依据。
- 复核有实际影响的口径。检查正常流程能否产生唯一结果，异常或边界下的资源与状态能否闭合。实现细节由开发决定，改变资格、资产、可达动作或测试结论的问题在功能讨论串确认。
- 发现问题时写明文档条款、具体场景、可能出现的不同结果和影响范围。可开发时记录所依据的版本、验收场景、明确使用的试玩初值和待接入的依赖，供功能建卡或原卡交接使用。
