# 需求输入与新建

1. 先回读本功能讨论串和相关决策，再对照总纲、已有需求和当前参考资料。遇到相同问题已被回答时，直接引用当时的口径。参考稿用于校对章节职责和表达方式，目标功能及规则以本项目确认内容为准。
2. 确定功能主体、范围和依赖。按操作前、成立时、结果生成和结果展示梳理行为，按需补截止、资源扣返、刷新恢复、失败和跨轮。
3. 先列已有依据和可能影响玩家的实际缺口。需要确认时，用一个可发生的场景说明两种处理会带来什么不同结果。可独立确认和编写的部分继续推进。
4. 按项目模板落在对应模块目录。写入后检查目标文件、版本、相邻模块引用和至少一个正常验收场景。试玩初值和固定的验收规则分别标注。
