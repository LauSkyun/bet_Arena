# 游戏需求编写

先从[玩法总纲](../../../requirements/overview.md)确定功能职责，再按[需求索引](../../../requirements/README.md)定位正式文件。新模块沿用[项目需求模板](../../../requirements/_template/requirement.md)。按[研发流程](../../../requirements/development-workflow.md)在该功能专属讨论串澄清，任务卡保留确认版本和交接入口。

| 当前任务 | 按需读取 |
| --- | --- |
| 从讨论稿、截图或参考资料新建需求 | [需求输入与新建](references/intake-and-creation.md) |
| 写规则、阶段、状态、资源与界面 | [需求正文写法](references/requirement-writing-standard.md) |
| 修改、评审或检查能否交给开发 | [需求修改与复核](references/review-edit-readiness.md) |

完整规则只写在负责它的模块，其他模块用链接说明自己的输入和输出。已确认规则、试玩初值和待确认事项分别标明。只有会改变玩家结果、开发可行性或验收口径的未决事项需要确认。
