# 里程碑 1 需求分析与测试范围

依据 [玩法总纲](../../requirements/overview.md) 与本项目六个模块的 v0.1 需求。以同一 H5 入口完成下注或观战、封盘、实际战斗回放、落账和续轮。执行用例见 [XMind](../cases/milestone-1.xmind)。

| 模块 | 需求侧的关键预期 | 回归或证据重点 |
| --- | --- | --- |
| [01 轮次与阶段](../../requirements/01-core-loop/requirement.md) | 同一轮次时间线推进；刷新重进恢复；上一轮落账后才续轮。 | 关键时点和浏览器恢复，余额只在应改变时改变。 |
| [02 下注与封盘](../../requirements/02-betting/requirement.md) | 首笔锁队、同队追加、请求幂等；封盘保存已确认投入与阵容。 | 错队、超限、截止及迟到回执；系统投入和玩家积分分别核对。 |
| [03 阵营、建造与兵种](../../requirements/03-build-and-roster/requirement.md) | 双方镜像开局，合法邻格扩建，混编仍属于原队，升级与满额使用配置。 | 固定随机值、边界和封盘快照，开战各三名基础兵。 |
| [04 自动战斗与占格](../../requirements/04-battle/requirement.md) | 以封盘阵容生成一次战斗；出兵、同刻行动与占格确定；限时占格给出唯一赛果。 | 补兵间隔、同刻冲突、废墟不计、基地被毁继续、刷新恢复、平局和作废。 |
| [05 积分结算](../../requirements/05-settlement/requirement.md) | 基于实扣与实际赛果落账，胜负平／作废／观战各自对应唯一余额。 | 结果与余额一同写入，双标签页与刷新不得重复扣或发。 |
| [06 竞技场界面](../../requirements/06-arena-ui/requirement.md) | 每阶段显示可操作项和已确认状态，结果字段与落账一致。 | 390 px 视口、正常入口完整两轮、封盘隐藏下注、战斗与结果刷新、上一轮摘要。 |

试玩使用测试积分和 v0.1 初值。浏览器内的同一站点会话是恢复范围。固定阵容与无效快照用于复现少见赛果，整局另按真实计时执行。最终玩家体验在里程碑卡单独记录。

表中的需求侧预期记录首轮 v0.1 验收。模块链接指向持续维护的需求文件，体验反馈后的新增口径见[迭代测试分析](milestone-1-iteration-2026-11-23.md)。
