# 下一轮时长设置自测

| 项目 | 内容 |
| --- | --- |
| 卡片 | #game研讨会:#15 |
| 依据 | [轮次与阶段 v0.2](../../requirements/01-core-loop/requirement.md) |
| 开发版本 | `c44475d7` |
| 入口 | 工作电脑 http://127.0.0.1:8765/timing/ |
| 环境 | Node 24.22.1，Windows Edge 390 px 视口、受控时钟 |

| 场景 | 实测结果 |
| --- | --- |
| 默认时长与输入 | 新会话显示 60 秒／40 秒。输入 0 秒出现错误并保留已保存值。输入 12 秒／18 秒后等待界面刷新，仍能提交草稿。 |
| 修改时的当前轮 | 保存 12 秒／18 秒后，原轮仍能在第 59 秒下注。第 60 秒封盘，第 82 秒战斗剩余 20 秒且进度为 50%，第 102 秒结算。双标签页显示相同阶段、时间和结算余额。 |
| 续轮与刷新 | 第 107 秒进入第 2 轮，两个标签页按 12 秒／18 秒运行，余额与上一轮落账一致。刷新仍显示同一设置和时间。 |
| 离开多轮后恢复 | 两个试玩页离开后，按受控时钟返回。页面进入第 6 轮，战斗剩余 17 秒，上一轮为第 5 轮，余额与离开前一致。 |
| 新建试玩 | 从第 6 轮确认新建后，返回第 1 轮，积分为 10,000，并沿用 12 秒／18 秒。 |
| Node 回归 | `node --test prototype-timing/*.test.mjs` 38 项通过。覆盖临界保存、超范围和小数、旧版时间线、封盘和结算、离线跨轮等。 |

浏览器通过正常界面提交配置并下单。旧会话版本迁移和截止点提交的精确边界由 Node 验证。Cindy 在原卡记录独立复核。
