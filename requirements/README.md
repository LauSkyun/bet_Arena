# requirements 目录规范（v0，临时版）

正式项目规范待定，以下先作为默认约定，等 @kaikai 拍板后替换。

## 目录结构

```
requirements/
  README.md                 # 本文件：命名与存放约定
  _template/                # 模板，不随功能改
    requirement.md          # 需求文档模板
    implementation.md       # 实现记录模板
  <编号>-<英文短名>/          # 每个功能一个文件夹
    requirement.md          # 需求文档（权威）
    implementation.md       # 实现记录（开发维护，策划核对）
```

## 命名

- 文件夹：`<两位编号>-<英文短名>`，例如 `01-core-loop`、`02-bet-settlement`。编号一经分配不改，功能拆分时新开编号，不重用。
- 需求文档固定名 `requirement.md`；实现记录固定名 `implementation.md`。
- 一个文件夹只放一个功能。功能变大时拆成新文件夹，原文件夹保留为父级索引（只写子功能清单和跳转）。

## 写作约定

- 需求文档以「玩家结果唯一」为准：同一规则只在一个章节完整定义，其余引用。
- UI 与红点在功能规则闭合后再定稿。
- 数值、文案、名称默认走配置，正文写关系、边界和玩家结果；确需固定值时在范围章声明。
- 未定事项写进「待确认项」，每条必须能产生两种不同的玩家结果。

## 状态

每个需求文档头部标注状态：`草稿` → `待确认` → `已确认` → `开发中` → `已验收` → `已废弃`。
