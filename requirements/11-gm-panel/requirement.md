## 1. 范围与入口

1. 运行范围为工作脑本机账号试玩服务，沿用现有试玩用户名登录方式。GM 设置从竞技场页账号导航的「GM 设置」进入 `/gm/`；直接访问 `/gm/` 也按同一权限规则处理。
2. 面板承载原 dev GM 的两类设置：下一轮结算模式（奖池／旧倍率）与模拟多人下注开关、人数、每人金额上下限。保留「下一新建轮次生效」口径，当前轮不变。
3. 面板不再要求手填密钥，也不展示或接收原始 JSON；用表单呈现选项，保存沿用本标签页的试玩账号会话身份。

## 2. 白名单与身份校验

1. 服务端用启动配置 `ARENA_GM_USERS`（逗号分隔的试玩用户名）建立白名单，按与账号相同的 NFKC 归一化＋小写规则取唯一键。未配置则无白名单账号。
2. 每次**读取管理面板**和**写入设置**都用请求携带的当前登录令牌解析账号，按其归一化键判断是否在白名单；不信任前端显示状态、不读取其他来源的身份。
3. 三种状态：
   - 未登录：面板显示登录入口。沿该入口登录后，在同一标签返回 GM 设置，再根据账号权限显示表单或只读摘要。登录前不显示当前配置。
   - 已登录但非白名单账号：面板显示「无修改权限」，可查看当前配置的只读文本，提交入口不可用。
   - 白名单账号：显示表单，可修改并保存。
4. 切换账号或退出后，权限随本标签会话变化：旧令牌失效即失去权限，新登录身份重新判定。普通账号即使绕过页面直接向写接口提交，也被服务端拒绝、配置保持不变。

## 3. 接口

1. `GET /api/gm/config`：返回 `{ signedIn, allowed, account?, gmConfig }`。未登录 `signedIn=false, allowed=false, gmConfig=null`；非白名单 `gmConfig` 为当前配置只读值。
2. `POST /api/gm/config`：按令牌身份校验，非白名单或未登录返回 403 且带错误信息；白名单按既有配置校验写入，返回 `{ gmConfig, roundNumber }`。不再接受 `X-GM-Key` 请求头作为授权。
3. 静态资源 `/gm/` 与其脚本样式按公开只读资源提供，页面自身不含任何权限数据。

## 4. 验收场景

| 场景 | 预期 |
| --- | --- |
| 白名单账号从竞技场进入并保存 | 表单可写，保存后下一轮生效，返回轮号正确。 |
| 普通账号直接打开 GM 页 | 显示无修改权限，配置只读，提交入口不可用。 |
| 普通账号直接提交设置接口 | 403，配置不变。 |
| 未登录打开 GM 页 | 显示登录入口。沿入口登录后，在同一标签返回 GM 页，白名单可写，普通账号只读。 |
| 同浏览器两标签分别登录 GM 与普通账号 | 各按本标签身份判权，互不串权限；切换到普通账号后 GM 表单消失。 |
| 退出后再次访问 | 旧令牌失效，回到未登录状态。 |
| 奖池／陪练选项与生效规则 | 与原 GM 一致：两类选项齐全、下一新轮生效、当前轮不变。 |

## 5. 配置方式

启动服务时设置 `ARENA_GM_USERS`，例如 `ARENA_GM_USERS='GM 管理,second-gm' node server/http.mjs`。实际白名单用户名由验收方配置；本实现只消费该配置并用规范化键比对。
